# 2026-10-05 : Budget (chances de réussir avec X Exalted, coût au 90e centile)

- `craft-solver/src/verify.rs` : `VerifyResult::cost_quantiles` (201 points, tous les 0,5 %, coût hors base
  neuve des essais réussis) et `success_probability(budget)` : palier inférieur des quantiles (jamais
  interpolé), essais interrompus = échecs. Coûts simulés stockés en f32 : tolérance relative 1e-6.
- UI : `src/lib/budget.ts` (même calcul + `budgetFor(p)`), bloc `BudgetBox` sous le récapitulatif du
  planificateur, champ `budget` dans le store. Sans vérification Monte-Carlo : message invitant à l'activer.
  Les fixtures du mode navigateur sont anciennes (pas de `costQuantiles`) : le bloc affiche alors ce message.
- Correctif trouvé en route : Désécration sur objet plein. Si le mod retiré libère un slot sans aucun mod
  Désécré possible (gants : Désécrés en suffixe seulement), le solveur perdait la probabilité (succès
  gratuit : plan annoncé 13 ex contre ~12 000 ex au moteur exact) et le moteur exact amputait l'objet.
  Désormais l'objet reste tel quel dans les deux (règle « reste tel quel » déjà utilisée pour les Essences ;
  le comportement exact du jeu dans ce cas n'est pas documenté, seul « un mod au hasard est retiré » l'est).
- Écart restant, NON corrigé : Alloys. L'état abstrait ne retient pas que le mod garanti d'une Alloy est déjà
  sur l'objet ; le moteur exact refuse alors l'Alloy (groupe déjà pris) et la politique boucle (24 % d'essais
  interrompus sur gants Vie/Feu/Froid T3).
- Tests : budget_success_probability_matches_closed_form (solveur), plan_reports_cost_distribution_for_budget_questions
  et desecration_on_full_gloves_keeps_solver_and_exact_engine_aligned (craft-api).
